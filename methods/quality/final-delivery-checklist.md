# Final delivery checklist

Complete this against the agreed scope. Record a named owner for each open
item. Client receipt is not the same as creative approval.

## Approval and scope

- [ ] Strategy sign-off has approver, date and version.
- [ ] Visual sign-off has approver, date and version, separate from strategy.
- [ ] Final deliverables match agreed scope and acceptance criteria.
- [ ] Exclusions, accepted exceptions and extensions are listed in writing.

## Files and formats

- [ ] Asset index lists name, purpose, variant, format, dimensions and version.
- [ ] Logo masters are supplied as agreed vector formats, typically SVG and PDF.
- [ ] Raster assets use agreed dimensions, transparency and stated format.
- [ ] Editable source files are included only where agreed and useful.
- [ ] Required colour spaces and profiles are named for digital and print.
- [ ] Files open correctly and match approved visual sign-off.
- [ ] Ambiguous duplicate exports and “final-final” names are removed.

## Typography and third-party rights

- [ ] Font families, weights and scripts have been tested in actual sample text.
- [ ] Font licences permit intended use; restricted font files are not bundled.
- [ ] Third-party images, illustrations and software are listed with rights.
- [ ] Required credits, notices and usage limits travel with the asset library.
- [ ] Client permissions cover intended use and agreed public disclosure.

## Guidelines and accessibility

- [ ] Guidelines include strategy, concept, logo use, clear space and minimum size.
- [ ] Guidelines include typography, supported scripts and size guidance.
- [ ] Colour values, roles, profiles and contrast pairings are documented.
- [ ] Composition, imagery, verbal foundations and examples are covered.
- [ ] Motion rules include purpose, reduced-motion behaviour and fallback where relevant.
- [ ] Digital examples were checked against WCAG 2.2 contrast as baseline.
- [ ] Colour-blind checks, non-colour cues and limits are recorded.
- [ ] Production notes cover relevant print, emboss, embroidery or vendor constraints.
- [ ] Known limitations and untested conditions are visible.

## Handover, permissions and archive

- [ ] Client recipient can access the agreed delivery location.
- [ ] Handover explains folder structure, current files and contact for questions.
- [ ] Archive manifest records final version, date, location and permissions.
- [ ] Client receipt is recorded separately from creative approval.
- [ ] Public case-study use has explicit permission; client files are not in public repo.
- [ ] Private project access is limited to named people and reviewed at close-out.
- [ ] Open items have an owner, status and agreed next step.
