# Identity system playbook

Who does what, with which tool, checked by whom, in each of the nine [identity engagement](../identity-engagement/README.md) phases. The phases run inside lifecycle stage L6 Deliver, with 08 closing into L7 and 09 into L9 ([client lifecycle](../lifecycle.md)). Read each phase's method file for the activities, research methods and quality criteria; this page does not repeat them. Field meanings, model routing and maker ≠ checker rules are in the [playbooks index](README.md).

## Before phase 01

- The workspace exists (follow [existing-workspace handling](README.md#workspace-and-evidence-discipline)): `bin/3w new project-identity --cleared` (contract permits anonymised publication) or `--private` (whole workspace in the vault). See [template bundles](../../templates/bundles/README.md).
- L5 kickoff has passed: plan, RACI, `C1` named as the single feedback consolidator, access through the vault, anonymised `projects/<codename>/brief.md`.
- Feedback limit is two consolidated rounds per phase (concept, refinement, applications) under [D-0023](../../studio/decisions/0023-commercial-and-delivery-defaults.md); further rounds are change orders (`bin/3w new change-order`).
- Production (`agency:project-management-studio-producer`) keeps `status/`, `decisions.md`, `feedback.md`, `risks.md` and the README gate log current throughout. That is not repeated below.

| [06 System](#06-system) | Design / identity-craft | `agent:visual-designer`; `agent:ui-ux-architect` for digital applications | `agency:design-brand-guardian`; `agent:frontend-architect` for digital rules | **Visual sign-off** | 3–5 working days |
| [07 Validation](#07-validation) | Design / design-qa | `agent:visual-qa-engineer` (digital); founder (print and physical) | `agency:testing-reality-checker` | Accepts known limits | 2–3 working days |
| [08 Delivery](#08-delivery) | Production / handover-retention with Design / identity-craft | `agency:project-management-studio-producer`; exports by `agent:bulk-executor` | `agency:testing-evidence-collector` | **Receipt and access** | 1–2 working days |
| [09 Learning](#09-learning) | Production; Operations / knowledge-systems | `agency:project-management-studio-producer` | `agent:strategic-architect` | Feedback and case-study permission | 1–2 working days, within two weeks of acceptance |

**Hypothesis** — the ranges sum to 19–32 working days before approval waits. The [identity offer](../../studio/identity-system-offer.md) proposes 4–6 weeks; the upper end here can exceed that. Production must reconcile scope, dependencies and founder capacity at L5 instead of presenting these ranges as a delivery commitment or measured duration.

Evidence labels used below: every phase output uses **Documented**, **Interpretation**, **Hypothesis** and **Unknown** exactly as the [critique protocol](../quality/critique-protocol.md#evidence-labels) defines them.

## 01 Discovery

Method: [01 Discovery](../identity-engagement/01-discovery.md).

| Field | Playbook |
| --- | --- |
| Objective | Establish what is known about the business, people, offer and context before interpreting the brief; record evidence and limits, choose no visual route. |
| Owner | Strategy / research-perception. Owner agent `agent:strategic-architect` (Opus) frames discovery and returns the synthesis; `agent:implementer` files the reviewed record. |
| Independent reviewer | `agency:research-synthesist`, in a separate instance from the maker, checks source weighting and evidence labels. Cross-department read: `agent:creative-director` confirms the synthesis can brief concept work and implies no route. |
| Lead tools | `skill:3w-brand-discovery` (brand-discovery); `skill:ux-research-methods` and `agency:project-management-experiment-tracker` (research-design); `skill:ux-research` (primary-research); `skill:customer-research` (source-collection); `skill:audience-belief-mapper` (audience-modelling). |
| Specialists (trigger) | `agent:researcher` — a stronger lead supplies exact fields, sources and inclusion criteria for lookup or extraction. `agency:design-ux-researcher` — inclusive recruitment or accessibility-focused participant research is needed. `agency:academic-statistician` — before any quantitative study, sample-size decision or causal claim. `skill:deep-research` — an explicitly scoped multi-source question. |
| Inputs | `projects/<codename>/brief.md` (from [client brief](../../templates/briefs/client-brief.md)); signed scope; client materials with provenance (vault `files/`); decision-maker access with consent. |
| Outputs | `projects/<codename>/discovery-synthesis.md` (pattern: the fictional [example](../../projects/examples/stillsoil-atelier/discovery-synthesis.md)); research intake from [the template](../../templates/learning/research-intake.md); source inventory; interview notes in `<vault>/<codename>/private-notes/`; open questions in `risks.md`. |
| Gate | No separate client gate; the factual summary goes to `C1` with phase 02. Founder approves the factual summary and participant handling. |
| Evidence | Every material claim linked to a source or labelled Hypothesis; consent and limits recorded; research-synthesist verdict in `qa/README.md`. |
| Pre-client quality check | Both cases in `evals/cases/strategy/evidence-synthesis/`. Follow `evals/README.md`; retain independent scores and human spot-check in `qa/README.md`. |
| Failure modes | Interviewing only the client founder and calling it audience research; agent-generated "insights" with no source; personal data copied into the public workspace; a mood board appearing in discovery. |

## 02 Diagnosis

Method: [02 Diagnosis](../identity-engagement/02-diagnosis.md).

| Field | Playbook |
| --- | --- |
| Objective | Turn discovery evidence into one bounded problem frame, a tension map and a sampled category view, without visual solutions. |
| Owner | Strategy / research-perception for the frame; Design / direction for the category audit. Owner agent `agent:strategic-architect`; the category audit is run by a Design instance under `agent:creative-director`. |
| Independent reviewer | `agency:research-synthesist` checks contradictions, sample scope and the alternative explanation. The maker of the category audit does not review it. |
| Lead tools | `skill:3w-category-code-audit` (category-audit); `agency:research-synthesist` (evidence-synthesis); `skill:category-narrative-mapper` (category-narratives); `agency:product-trend-researcher` (market-signals, only when a dated trend could change the problem). |
| Specialists (trigger) | `agency:specialized-cultural-intelligence-strategist` (cultural-systems lead) — cultural meaning affects the frame. `agency:academic-historian` (historical-context lead) — a heritage or provenance reference needs verification. `agency:academic-anthropologist` — a sourced cultural or ritual question affects intended meaning. [`skill:3w-behavioural-lens`](../../toolkit/cards/strategy/culture-behaviour/skill--3w-behavioural-lens.md) (behavioural-theory lead) — a decision rests on observable behaviour and needs a sourced mechanism, ethics screen and falsifiable test. [`skill:3w-narrative-analysis`](../../toolkit/cards/strategy/culture-behaviour/skill--3w-narrative-analysis.md) (narrative-analysis lead) — sourced founder, customer or cultural stories could change the diagnosis; verify load-bearing claims rather than polish them. |
| Inputs | Discovery synthesis and source inventory; signed scope; category sample (links in the audit). |
| Outputs | `projects/<codename>/diagnosis.md`: diagnosis statement, tension map, category convention and white-space note (only if the sample supports it), prioritised questions for strategy. |
| Gate | **Discovery and diagnosis gate:** `C1` confirms factual accuracy and the work question; founder logs it. This does not approve an interpretation or concept. |
| Evidence | Linked category samples with stated selection bias; evidence matrix; at least one alternative explanation; `C1` confirmation in `decisions.md`. |
| Pre-client quality check | Both cases in `evals/cases/strategy/evidence-synthesis/`; both cases in `evals/cases/strategy/positioning-canvas/`. Follow `evals/README.md`; retain independent scores and human spot-check in `qa/README.md`. |
| Failure modes | Claiming white space from a convenience sample; an aesthetic preference written as a diagnosis; treating every category convention as bad. |

## 03 Strategy

Method: [03 Strategy](../identity-engagement/03-strategy.md). **Strategy approval is separate from, and earlier than, visual approval.**

| Field | Playbook |
| --- | --- |
| Objective | Set one coherent direction, positioning, promise boundaries and the creative criteria concepts will be judged against. |
| Owner | Strategy / positioning. Owner agent `agent:strategic-architect`; `agent:ceo` when the project is a flagship or the studio's own identity. |
| Independent reviewer | `agency:specialized-strategy-duel-agent` argues both sides of the positioning (its scores are hypotheses; factual claims are re-verified). `agent:creative-director` checks that the creative criteria can actually judge routes. |
| Lead tools | `skill:positioning-mapper` (positioning-canvas); `skill:positioning-truth-tracer` (positioning-proof); `skill:category-narrative-mapper` (category-narratives); `skill:audience-belief-mapper` (audience-modelling). |
| Specialists (trigger) | `agency:business-strategist` — the brief needs explicit competitive choices. `design-skills:ux-strategy` — a documented identity problem needs JTBD or a value-proposition bridge. `agent:creative-writer` — wording of the positioning and proof boundaries for presentation. |
| Inputs | Reviewed diagnosis; source notes; unresolved questions; approved scope and decision roles. |
| Outputs | `projects/<codename>/strategy.md` from [strategy on a page](../../templates/strategies/strategy-on-a-page.md); hypotheses list; signed version recorded in `decisions.md` and the gate log. |
| Gate | Founder approves the strategy for presentation. **`C1` signs a dated strategy version** before phase 04 starts. Present without visual references. A later material change returns here and is recorded before concept work resumes. |
| Evidence | Every factual promise sourced or marked as an ambition; comprehension check (client restates audience, choice and proof); duel-agent and creative-director notes in `qa/README.md`. |
| Pre-client quality check | Both cases in `evals/cases/strategy/positioning-canvas/`. Follow `evals/README.md`; retain independent scores and human spot-check in `qa/README.md`. |
| Failure modes | A mood board approved as if it were strategy; promises of results the project cannot control; several incompatible audiences left unresolved; jargon hiding missing logic. |

## 04 Concept

Method: [04 Concept](../identity-engagement/04-concept.md). Hand-in: [strategy → design](../handoffs/strategy-to-design.md).

| Field | Playbook |
| --- | --- |
| Objective | At least three conceptually distinct territories in words and rough sketches, critiqued, with one recommended route. |
| Owner | Design / direction. Owner agent `agent:creative-director` running `skill:3w-creative-direction`; `agent:ceo` for flagship and own-identity routes. The founder leads taste and route judgement. |
| Independent reviewer | Independent `agency:design-brand-guardian` on Opus with `skill:3w-identity-system-critic`, concept mode first. Use `agent:ceo` only for flagship/own-identity critique when it did not direct the work. Originality: `skill:audit-reference-originality` against the actual `taste/` sources and the category audit. Strategy fit: `agent:strategic-architect` (did not make the routes). |
| Lead tools | A reference pack from the [`3w-taste-graph`](../../skills/3w-taste-graph/SKILL.md) skill first (registered creative-output prerequisite) (studio rule); `skill:taste-skill` (inspiration-taste); `agent:creative-director` and `skill:3w-creative-direction` (concept-direction); `anthropic-skills:world-class-copywriter` (verbal-identity) for route naming and idea statements. Sketches remain concept exploration here; [`skill:3w-mark-exploration`](../../toolkit/cards/design/identity-craft/skill--3w-mark-exploration.md) leads mark-logo in phase 05 after route selection, not before its prerequisite. |
| Specialists (trigger) | `agent:ceo` — a flagship or the studio's own identity needs a consequential concept decision. `skill:generate-reference-inspired-brand-worlds` or `skill:gstack-design-shotgun` — exploring several distinct territories (load one, not both). `agent:creative-writer` — identity copy for route presentation. `design-superpowers:creative` — rough digital direction alternatives after strategy approval. |
| Inputs | Signed strategy and criteria; category view; reference pack with its never-copy list. |
| Outputs | `projects/<codename>/concept-route-a.md`, `-b.md`, `-c.md` from the [concept route template](../../templates/identity-systems/concept-route.md); critique record from the [design critique template](../../templates/critique/design-critique.md) in `qa/`; rejected routes kept with reasons; route decision in `decisions.md`. |
| Gate | Founder chooses the route to recommend. **`C1` selects a route for development** (concept decision, not visual sign-off). Under D-0023 the 30% payment falls on approval of the chosen direction: Operations raises it with `bin/3w new invoice` (vault only). |
| Evidence | Each idea described without visual adjectives; verdict "Strong enough to advance" on the recommended route; originality report; maker and checker named per version. |
| Pre-client quality check | Both cases in `evals/cases/design/concept-direction/`; both cases in `evals/cases/design/concept-critique/`. Follow `evals/README.md`; retain independent scores and human spot-check in `qa/README.md`. |
| Failure modes | Three colourways of one idea presented as three routes; one polished answer as "exploration"; references standing in for an ownable idea; the D-0006 rejected vocabulary creeping in as a default. |

## 05 Identity

Method: [05 Identity](../identity-engagement/05-identity.md). Type, mark, colour and composition decisions are human-led; AI explores, prepares variations and checks.

| Field | Playbook |
| --- | --- |
| Objective | Express the selected route as a coherent set of visual and verbal elements, each traceable to the idea and the signed strategy. |
| Owner | Design / identity-craft. The founder decides; `agent:visual-designer` (Opus) executes the approved digital system; `agent:implementer` records the human-led mark and cross-format craft work under the four W1 lead methods. |
| Independent reviewer | `agency:design-brand-guardian` running `skill:3w-identity-system-critic`, formal mode (hierarchy, type, composition, colour, scale, language), with a human craft reader. If digital work is in scope, `agent:frontend-architect` reads the token draft for feasibility. |
| Lead tools | typography: [`skill:3w-typography-system`](../../toolkit/cards/design/identity-craft/skill--3w-typography-system.md). colour: [`skill:3w-colour-system`](../../toolkit/cards/design/identity-craft/skill--3w-colour-system.md). mark-logo: [`skill:3w-mark-exploration`](../../toolkit/cards/design/identity-craft/skill--3w-mark-exploration.md). composition-layout: [`skill:3w-composition-system`](../../toolkit/cards/design/identity-craft/skill--3w-composition-system.md). verbal-identity: `anthropic-skills:world-class-copywriter`. image-generation-direction: `anthropic-skills:gpt-image-2-director`. design-system-guidelines: `design-skills:design-systems`. |
| Specialists (trigger) | `agent:visual-designer` — the chosen type/colour system needs digital tokens, a type ramp, measured contrast table and grid specification. [`skill:3w-image-production`](../../toolkit/cards/media/image-photo-direction/skill--3w-image-production.md) (image-production-workflow lead) — approved image direction needs assets; [`skill:3w-image-qa`](../../toolkit/cards/media/image-photo-direction/skill--3w-image-qa.md) (image-quality-check lead) — a separate checker screens the produced or supplied set before use. `vectorlab-ux-skills:typography` — a digital type hierarchy has a scale, weight or line-height defect. `vectorlab-ux-skills:colour-palette` — only after the human colour direction is approved. `design-skills:design-elevation` — concept approved and a bounded artefact needs hierarchy refinement. `skill:brand-language-codifier` — defining voice, naming rules or brand language. `agency:design-inclusive-visuals-specialist` — image direction needs inclusive review. `skill:ceos-motion-direction` — only if motion is in scope ([living identities](../living-identities.md)). |
| Inputs | Route decision; signed strategy; usage contexts, languages and scripts; font, image and software licences. |
| Outputs | `projects/<codename>/identity-system-spec.md` from the [specification template](../../templates/identity-systems/identity-system-spec.md) (first version); source files in `<vault>/<codename>/files/`; rights and open-issues register in `risks.md`, licence documents in the vault. |
| Gate | No client visual gate here. Founder signs the craft; `C1` confirms product language and required scripts. Component review does not approve the system. |
| Evidence | Logo tested at intended sizes and in one colour; specimen strings for real names, numerals and every required script, checked by a fluent reviewer where needed; contrast measured for digital pairs; licence terms read. |
| Pre-client quality check | Both cases in `evals/cases/design/verbal-identity/`; both cases in `evals/cases/design/typography/`; both cases in `evals/cases/design/colour/`; both cases in `evals/cases/design/mark-logo/`; both cases in `evals/cases/design/composition-layout/`. Follow `evals/README.md`; retain independent scores and human spot-check in `qa/README.md`. |
| Failure modes | A typeface chosen by mood that lacks a script or licence; a logo treated as the whole identity; colour alone carrying meaning; AI-generated finals without the client's written consent (D-0023); AI images presented as exclusive logo artwork. |

## 06 System

Method: [06 System](../identity-engagement/06-system.md). Digital applications bring Engineering in now, not at handover ([design → engineering](../handoffs/design-to-engineering.md)).

| Field | Playbook |
| --- | --- |
| Objective | Turn elements into repeatable rules and test them on at least three unlike, in-scope applications. |
| Owner | Design / identity-craft. the founder leads cross-format applications; `agent:visual-designer` makes digital specimens; `agent:ui-ux-architect` owns digital applications and responsive rules; the founder decides exceptions. |
| Independent reviewer | `agency:design-brand-guardian` runs `skill:3w-brand-consistency-qa` and the second critique pass; `agent:frontend-architect` checks digital rules and token naming map to code. |
| Lead tools | `design-skills:design-systems` (design-system-guidelines); `skill:3w-brand-consistency-qa` (consistency-qa, reviewer side only); [`skill:3w-composition-system`](../../toolkit/cards/design/identity-craft/skill--3w-composition-system.md) (composition-layout); `skill:audit-reference-originality` before anything is presented. |
| Specialists (trigger) | `agency:design-brand-guardian` — scope requires design-system guidelines expertise. `skill:dataviz` — an application needs charts with supplied, verified data. `ui-ux-pro-max:banner-design` — an agreed application needs a banner at specified dimensions. `design-steward:align` — the founder has decided a change and tokens or documents must follow. |
| Inputs | Identity elements; channel, format and production constraints; [identity system testing](../quality/identity-system-testing.md) matrix. |
| Outputs | Tested `identity-system-spec.md` (invariants, variables, digital rules, motion principles, exceptions); representative applications in `<vault>/<codename>/files/`; defect and exception log in `qa/README.md`. |
| Gate | Founder approves the system for presentation. **`C1` gives visual sign-off**, separate from the strategy sign-off. A strategy change returns to 03; a production defect returns to its rule. |
| Evidence | At least three unlike applications, or recorded limits; long and short names, dense and sparse content, small sizes and one-colour use; a person unfamiliar with the route applies the rules to a new example. |
| Pre-client quality check | Both cases in `evals/cases/design/composition-layout/`; both cases in `evals/cases/design/consistency-qa/`. Follow `evals/README.md`; retain independent scores and human spot-check in `qa/README.md`. |
| Failure modes | One hero mock-up; mock-up lighting hiding weak contrast; a "flexible" system that needs custom art direction every time; vendor and language constraints left for delivery. |

### Motion and living identity at system planning

Apply the [living-identity decision test](../living-identities.md#decision-test)
when phase 04 proposes motion and phase 06 plans the system. Under
[D-0025](../../studio/decisions/0025-creative-technology-selection-policy.md),
use the [selection policy](../creative-technology/selection-policy.md) and
[living-identity matrix](../creative-technology/selection-matrix.md#6-living-identities)
to compare SVG/GSAP, Rive and Lottie/dotLottie for the actual requirements.
Art-directed states and behaviours differ from a generative system's rules and
inputs; data binding alone does not make an identity generative. Prove the
static invariant, meaningful fallback, reduced-motion path and maintenance
owner before adding either. Record the choice and prototype evidence; web
delivery meets D-0023. Complex 3D or custom-code extensions need separate scope.
Carry these records into phase 07 validation and phase 08 handover.

## 07 Validation

Method: [07 Validation](../identity-engagement/07-validation.md).

| Field | Playbook |
| --- | --- |
| Objective | Check the approved system against real content, accessibility and production conditions before packaging. |
| Owner | Design / design-qa. `agent:visual-qa-engineer` tests digital examples in a real browser; the founder coordinates print and physical proofs with the vendor; a second human who did not make the artwork inspects the physical result. If unavailable, record physical QA as not verified. |
| Independent reviewer | `agency:testing-reality-checker` reviews the validation record and retest evidence (defaults to "needs work" until proven). Cultural check on request: `agency:specialized-cultural-intelligence-strategist` as an independent reviewer. |
| Lead tools | `skill:3w-identity-system-critic` (concept-critique); `skill:3w-brand-consistency-qa` (consistency-qa); `design-skills:accessibility-audit` (accessibility); `agent:visual-qa-engineer` (visual-qa-browser); `skill:audit-reference-originality` (originality-audit). |
| Specialists (trigger) | `vectorlab-ux-skills:reduced-motion` — a motion treatment needs a tested reduced-motion alternative. `agency:testing-accessibility-auditor` or `design:accessibility-review` — scope requires accessibility expertise (load one). `agency:design-inclusive-visuals-specialist` — imagery needs inclusive review. |
| Inputs | Signed visual system; test matrix; representative content and output conditions; vendor criteria. |
| Outputs | Completed [identity system testing](../quality/identity-system-testing.md) matrix in `qa/README.md`; defect log with severity, owner, fix and retest; validation notes listing untested conditions. |
| Gate | Founder (as design lead) signs the validation record. `C1` accepts known limits and residual exceptions in writing (`decisions.md`). |
| Evidence | Actual exports at in-scope sizes (including 16 px favicon and large format when scoped), monochrome and reverse; contrast measured against WCAG 2.2 for digital text; colour-vision screening plus real inspection; print proofs with stock, inks and process recorded; motion in normal and reduced-motion settings; retest of every fix. |
| Pre-client quality check | Both cases in `evals/cases/design/concept-critique/`; both cases in `evals/cases/design/consistency-qa/`; both cases in `evals/cases/engineering/accessibility-implementation/`. Follow `evals/README.md`; retain independent scores and human spot-check in `qa/README.md`. |
| Failure modes | A simulator as the only accessibility test; print effects judged on screen; WCAG claimed from one colour pair; exports not retested after revisions. |

## 08 Delivery

Method: [08 Delivery](../identity-engagement/08-delivery.md). Lifecycle L7. Hand-off: [QA → production and handover](../handoffs/qa-to-handover.md).

| Field | Playbook |
| --- | --- |
| Objective | Package the approved identity, guidance and rights information so the client can find, use and maintain it. |
| Owner | Production / handover-retention coordinates (`agency:project-management-studio-producer`); Design / identity-craft owns guidelines and source files; `agent:bulk-executor` runs mechanical exports and file naming from Design's written list; Operations / finance-legal checks licence and ownership terms. |
| Independent reviewer | `agency:testing-evidence-collector` opens every delivered file against the asset index and the [final-delivery checklist](../quality/final-delivery-checklist.md). |
| Lead tools | `design:design-handoff` (handover-specs); `anthropic-skills:pptx` (presentation) where a deck is agreed; `agency:legal-document-review` (legal-contracts) for licence and ownership wording. Use [`skill:3w-mark-exploration`](../../toolkit/cards/design/identity-craft/skill--3w-mark-exploration.md) for mark-vector readiness and [`skill:3w-composition-system`](../../toolkit/cards/design/identity-craft/skill--3w-composition-system.md) for application templates. | Gate | Founder approves release. **`C1` confirms receipt and access**, recorded separately from creative approval; receipt is not a new creative approval. |
| Evidence | Checklist complete or each exception recorded; files opened in the relevant software; vector scale, raster sizes, colour profiles checked; delivery link verified with the named recipient. |
| Pre-client quality check | Both cases in `evals/cases/design/consistency-qa/`. Follow `evals/README.md`; retain independent scores and human spot-check in `qa/README.md`. |
| Failure modes | Mock-ups without usable source files; font or image files bundled without permission; "final-final" naming; assuming a sent link opens. |
