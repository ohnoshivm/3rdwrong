# Creative Technology learning library

**Interpretation** — Proposed learning programme adapted from section 14 of
[the founder's handbook](../../studio/archive/creative-technology-handbook-2026-10.md).
These resources are study inputs, not approved dependencies or evidence of
studio competence. Follow the [selection policy](selection-policy.md) when
applying a lesson; check a project's exact versions against official docs.

## Resources and learning outputs

| Resource | What to learn | Required study output |
| --- | --- | --- |
| [Three.js Journey](https://threejs-journey.com/) | Three.js fundamentals, shaders, physics and advanced scene construction | One original scene with a lighter alternative, device evidence and critique. Paid course access needs founder approval. |
| [Three.js examples](https://threejs.org/examples/) | Working rendering, materials, loaders and interaction techniques | Explain one technique and rebuild a small original fixture; record versions, licence and resource cleanup. |
| [OGL examples](https://oframe.github.io/ogl/examples/) | Focused WebGL abstractions, uniforms and shader experiments | One shader transition compared with CSS/SVG or a fixed transition. |
| [GSAP resources](https://gsap.com/resources/) | Choreography, ScrollTrigger and timeline architecture | One readable typography or scroll study with clear ownership, cleanup and reduced motion. |
| [Codrops](https://tympanus.net/codrops/) | Experimental interactions and creative coding research | Extract a transferable principle; build a different composition with original assets/code. Tutorial availability is not blanket licence clearance. |
| [Theatre.js](https://www.theatrejs.com/) | Visual sequencing and art-directed keyframes | Compare authoring a short camera sequence with GSAP; record export, dependency and maintenance cost. |
| [React Three Fiber docs](https://r3f.docs.pmnd.rs/) | React scene architecture, render loops and production performance | Justify React first, record stable/alpha versions and test the actual renderer/material stack. |
| [14islands Scroll Rig](https://github.com/14islands/r3f-scroll-rig) | DOM and persistent-canvas alignment | Compare a small aligned fixture with manual DOM measurement/native scroll; test resizing and fallback. |
| [Rive](https://rive.app/) | Interactive identity, state machines and data contracts | One authored state system with keyboard/HTML controls, static fallback and maintainable handover. Compare SVG and dotLottie. |
| [web.dev](https://web.dev/) | Performance engineering and Core Web Vitals | A reproducible lab report with field-data limits and a D-0023 budget comparison. |

## Learning priority

GSAP → creative CSS/SVG → shaders/OGL → Three.js/R3F → Rive → advanced
rendering and simulation. This is organisational learning order, not an
artistic ranking or permission to skip native-first selection. Typography,
composition and content craft continue throughout. Use the
[taste discovery sources](../../taste/discovery-sources.md) and
[studio reference studies](../../taste/studio-websites.md) for principles,
never as a selected 3RDWRONG look.

## Five starter studies

The [Labs repertoire backlog](../../experiments/creative-technology-repertoire.md)
defines one typography interaction, shader transition, scroll narrative,
interactive 3D scene and generative identity. Study → recreate internally →
critique → improve → document. Internal recreation is a learning step, not a
publishable derivative; it does not waive licence or data rules. Public output
must be original in layout, assets and code, with licensed dependencies credited.

## Learning record

Use the [experiment template](../../templates/learning/experiment.md): question,
hypothesis, references and provenance, chosen stack and alternatives, versions,
what was attempted, observed result, critique, improvement, device/accessibility
measurements, failure cases, limits and adopt/iterate/drop decision. Label
**Documented**, **Interpretation**, **Hypothesis** and **Unknown** precisely.
A technique enters the house engine only after independent validation; a client
project still needs its own stack record and budget evidence.
