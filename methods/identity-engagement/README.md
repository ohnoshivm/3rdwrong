# Identity engagement method

This proposed sequence moves from evidence to learning. A phase produces the
inputs needed by the next; dates and client commitments are agreed separately.

| Phase | Purpose | Supporting skill or template |
| --- | --- | --- |
| [01 Discovery](01-discovery.md) | Establish source-backed understanding | `brand-discovery`; perception-to-identity map; research intake; client brief |
| [02 Diagnosis](02-diagnosis.md) | Frame the problem and category context | `category-code-audit`; perception-to-identity map; research intake |
| [03 Strategy](03-strategy.md) | Set direction and criteria | Perception-to-identity map; strategy on a page |
| [04 Concept](04-concept.md) | Develop and compare ideas | `creative-direction`; concept route; design critique |
| [05 Identity](05-identity.md) | Build the selected identity elements | Identity system specification |
| [06 System](06-system.md) | Test repeatable rules across applications | `brand-consistency-qa`; identity system specification |
| [07 Validation](07-validation.md) | Check evidence, access and production constraints | `identity-system-critic`; system test matrix |
| [08 Delivery](08-delivery.md) | Package approved assets and guidance | Final-delivery checklist |
| [09 Learning](09-learning.md) | Record lessons and revise responsibly | Retrospective; method improvement; skill evaluation |

## Workflow crosswalk

The blueprint's eight-step workflow is a source model; this studio method
retains nine operational phases by separating the final delivery from the
learning review. Source: *Founding Blueprint v1.0, 22 October 2026 (private
archive)*.

| Blueprint step | Studio phase | What moves forward |
| --- | --- | --- |
| Discover | 01 Discovery | Source inventory, research notes, evidence limits |
| Diagnose | 02 Diagnosis | Bounded problem frame, tensions and open questions |
| Define | 03 Strategy | Signed direction, promise boundaries and creative criteria |
| Explore | 04 Concept | Distinct territories and a human route decision |
| Design | 05 Identity | Selected idea expressed in core identity elements |
| Systematise | 06 System | Invariants, variables, rules and applications |
| Validate | 07 Validation | Tested fit, recognition, access and production evidence |
| Deliver & learn | 08 Delivery + 09 Learning | Accepted handover, then a separate retrospective and reusable learning |

## Approval gates

| Gate | Required human decision | What the gate does not approve |
| --- | --- | --- |
| Discovery and diagnosis | Confirm factual inputs and the work question | Does not approve an interpretation or concept |
| Strategy, after phase 03 | Named decision-maker signs a dated strategy version | Does not approve a visual route or logo |
| Concept, after phase 04 | Select a route for development | Does not approve final system applications |
| Visual system, after phase 06 | Named decision-maker signs the tested visual direction | Does not reopen strategy by implication |
| Delivery, after phase 08 | Client confirms receipt and access | Receipt is not a new creative approval |

Strategy approval is a hard prerequisite for phase 04. Strategy and visual
approval are separate. A material strategy change returns to phase 03 and is
recorded before concept work resumes. Human approval is required wherever the
phase says so; no skill or automated check may mark work approved.

## Phase files

Each phase has the same nine required sections: Objective; Required inputs;
Activities; Research methods; Deliverables; Quality criteria; Common failure
modes; Human approval; Completion conditions. Read the phase file for the
actual checks rather than inferring a gate from this index.
