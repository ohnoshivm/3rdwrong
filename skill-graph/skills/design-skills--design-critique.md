# Design Critique

_Generated by `scripts/build_skill_graph.py` from the registry and cards. Edit the source, not this note._

Design Critique is a 3RDWRONG design QA specialist for ux-audit, activated when a supplied interaction flow needs a heuristic evaluation with explicit findings.

- **Role:** specialist
- **Job:** [[design--ux-audit|ux audit]] (design-qa)
- **Department:** [[skill-graph/Design|Design]]
- **Card:** `toolkit/cards/design/design-qa/design-skills--design-critique.md`
- **Invoke:** /design-critique

## What it does

- Reviews a supplied design using usability heuristics, UX laws, interaction patterns, IA and content quality.
- Starts with user, task, journey stage and constraints, then runs a five-second scan.
- Records heuristic violations with severity and specific fixes; synthesises by impact.
- Grounds critique in principles and evidence rather than personal preference.

## When to use

- A supplied interaction flow needs a heuristic evaluation with explicit findings. In practice: during experience design or validation, against the named user task and flow.

## When not to use

- Do not use it to certify accessibility or production readiness; use `skill:accessibility` for design-level access risks and `skill:reviewing-interface-quality` for rendered interface quality.

## How to run it

1. Confirm the exact surface, task, scope and evidence before judging.
2. Apply only the source tool’s relevant method and record concrete observations.
3. Prioritise findings by user consequence and pair each with a usable next action.
4. State evidence gaps and route any specialist checks to the relevant owner.
