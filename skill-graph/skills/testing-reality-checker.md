## What it does

- Cross-checks QA claims against implementation, screenshots and test results.
- Reviews complete user journeys and responsive evidence rather than accepting scores at face value.
- Flags missing proof, broken interactions and mismatches between specification and build.
- Keeps untested work distinct from defects and withholds production-readiness claims without evidence.

## When to use

- When the approved scope specifically requires consistency qa expertise. In practice: phase 07 validation or the relevant handoff, against the current approved system.

## When not to use

- Do not use it to choose the strategy or approve its own work; use `skill:3w-brand-consistency-qa` for identity assets against an approved baseline.

## How to run it

1. Confirm the baseline is approved and current; if not, stop conformance scoring.
2. Inventory the supplied scope and compare each item only to applicable written requirements.
3. Record evidence and status for every check; mark missing measurement, production or rights proof Not testable.
4. Hand failures and retest criteria to a separate maker; leave release approval to the authorised human.

```text
Use agency:testing-reality-checker for this consistency-qa review. Scope: {{surface, phase and decision}}. Inputs/evidence: {{links, files, versions and states}}. Apply only the documented method. Separate Documented, Interpretation, Hypothesis and Unknown where evidence claims are made; mark untested checks explicitly. Return the tool's required output structure with findings, evidence and concrete next actions.
```
