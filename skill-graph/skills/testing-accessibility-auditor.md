# Accessibility Auditor

_Generated by `scripts/build_skill_graph.py` from the registry and cards. Edit the source, not this note._

Accessibility auditor is a 3RDWRONG design QA specialist for accessibility, activated when the approved scope specifically requires accessibility expertise.

- **Role:** specialist
- **Job:** [[design--accessibility|accessibility]] (design-qa)
- **Department:** [[skill-graph/Design|Design]]
- **Card:** `toolkit/cards/design/design-qa/agency--testing-accessibility-auditor.md`
- **Invoke:** Agent tool: testing-accessibility-auditor

## What it does

- Audits accessibility through automated checks and manual interaction review.
- Checks keyboard navigation, focus, screen reader output, semantics, contrast, forms and responsive behaviour.
- Reports issues with evidence, severity and remediation guidance.

## When to use

- When the approved scope specifically requires accessibility expertise. In practice: before implementation sign-off or release, for the supplied design or implemented flow.

## When not to use

- Do not claim compliance from a static artefact or automated scan alone; use `agency:engineering-section-508-specialist` for a deeper engineering/document audit.

## How to run it

1. Name the target level and inspect the supplied artefact with the tool’s documented visual/manual methods.
2. Separate visible risks from code, keyboard, assistive-technology and responsive checks.
3. Prioritise by access impact, cite the affected control/state, and recommend a concrete correction.
4. Record what was tested and what remains unverified; do not claim conformance without evidence.

