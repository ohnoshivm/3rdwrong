# Audit

_Generated by `scripts/build_skill_graph.py` from the registry and cards. Edit the source, not this note._

Audit is a 3RDWRONG design QA specialist for ux-audit, activated when an existing project has conflicting design decisions and needs a cited source/provenance audit.

- **Role:** specialist
- **Job:** [[design--ux-audit|ux audit]] (design-qa)
- **Department:** [[skill-graph/Design|Design]]
- **Card:** `toolkit/cards/design/design-qa/design-steward--audit.md`
- **Invoke:** /audit

## What it does

- Finds durable design decisions across tokens, code defaults, docs and prior review artefacts.
- Traces provenance and confidence, and identifies contradictions or implicit rules.
- Supports full audit and targeted gate modes; requires citations for every finding.
- Writes a canon report and source snapshot to the project’s design-steward run folder.

## When to use

- An existing project has conflicting design decisions and needs a cited source/provenance audit. In practice: during experience design or validation, against the named user task and flow.

## When not to use

- Do not use it to certify accessibility or production readiness; use `skill:accessibility` for design-level access risks and `skill:reviewing-interface-quality` for rendered interface quality.

## How to run it

1. Confirm the exact surface, task, scope and evidence before judging.
2. Apply only the source tool’s relevant method and record concrete observations.
3. Prioritise findings by user consequence and pair each with a usable next action.
4. State evidence gaps and route any specialist checks to the relevant owner.

```text
Use design-steward:audit for this ux-audit review. Scope: {{surface, phase and decision}}. Inputs/evidence: {{links, files, versions and states}}. Apply only the documented method. Separate Documented, Interpretation, Hypothesis and Unknown where evidence claims are made; mark untested checks explicitly. Return the tool's required output structure with findings, evidence and concrete next actions.
```
