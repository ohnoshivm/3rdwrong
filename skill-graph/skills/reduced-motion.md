# Reduced Motion

_Generated by `scripts/build_skill_graph.py` from the registry and cards. Edit the source, not this note._

Reduced Motion is a 3RDWRONG design QA specialist for accessibility, activated when a supplied motion treatment needs a tested prefers-reduced-motion alternative.

- **Role:** specialist
- **Job:** [[design--accessibility|accessibility]] (design-qa)
- **Department:** [[skill-graph/Design|Design]]
- **Card:** `toolkit/cards/design/design-qa/vectorlab-ux-skills--reduced-motion.md`
- **Invoke:** /reduced-motion

## What it does

- Checks a supplied motion treatment for a tested `prefers-reduced-motion` alternative.
- Reviews whether reduced-motion behaviour is intentional and usable.
- Requires an actual alternative state rather than assuming a CSS declaration proves it.

## When to use

- A supplied motion treatment needs a tested prefers-reduced-motion alternative. In practice: before implementation sign-off or release, for the supplied design or implemented flow.

## When not to use

- Do not claim compliance from a static artefact or automated scan alone; use `agency:engineering-section-508-specialist` for a deeper engineering/document audit.

## How to run it

1. Name the target level and inspect the supplied artefact with the tool’s documented visual/manual methods.
2. Separate visible risks from code, keyboard, assistive-technology and responsive checks.
3. Prioritise by access impact, cite the affected control/state, and recommend a concrete correction.
4. Record what was tested and what remains unverified; do not claim conformance without evidence.
