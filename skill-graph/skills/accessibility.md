# Accessibility

Accessibility is a 3RDWRONG design QA specialist for accessibility, activated when the approved scope specifically requires auditing or building accessible digital experiences.

- **Role:** specialist

- **Invoke:** /accessibility

## What it does

- Reviews design artefacts against WCAG 2.1 A/AA and POUR.
- Flags visible risks such as contrast, labels, hierarchy, focus affordances, colour-only meaning and target size.
- Separates screenshot-visible findings from semantic, keyboard, screen reader and responsive implementation checks.
- Uses a concise verdict and prioritised recommendations.

## When to use

- When the approved scope specifically requires auditing or building accessible digital experiences. In practice: before implementation sign-off or release, for the supplied design or implemented flow.

## When not to use

- Do not claim compliance from a static artefact or automated scan alone; use `agency:engineering-section-508-specialist` for a deeper engineering/document audit.

## How to run it

1. Name the target level and inspect the supplied artefact with the tool’s documented visual/manual methods.
2. Separate visible risks from code, keyboard, assistive-technology and responsive checks.
3. Prioritise by access impact, cite the affected control/state, and recommend a concrete correction.
4. Record what was tested and what remains unverified; do not claim conformance without evidence.
