Critic Layer is a 3RDWRONG design QA specialist for visual-qa-browser, activated when an independent reviewer needs an in-browser annotated critique capture.

## What it does

- Captures live-page notes, drawings and direct element edits through an on-page HUD.
- Preserves the designer’s intent first, then may add clearly attributed AI suggestions.
- Synthesises captures into an agent-ready change brief and Claude Code prompt.
- Live edits are previews, not source changes; it is not an autonomous redesign agent or crawler.

## When to use

- An independent reviewer needs an in-browser annotated critique capture. In practice: during Phase 07 Validation when an independent reviewer can annotate the named live page.

## When not to use

- Do not use it for unrendered concept critique or to make fixes unless its source explicitly allows edits; use `skill:3w-identity-system-critic` for identity concepts.

## How to run it

1. Confirm the page loads and capture the stated widths/states before reporting.
2. Exercise the named flow; inspect screenshots and measurements that support each finding.
3. Report location, observed/expected behaviour, impact, evidence and fix owner.
4. Mark inaccessible or untested widths and behaviours unverified, then re-check fixes against the same evidence.
